侧边栏新增功能：每日分配

一、目标
- 在 Toolbox.app 侧边栏新增“每日分配”功能。
- 输入：源文件1（AI待分配表）、源文件2（答题卡待分配表）、报名截图（可多张）。
- 输出：分配表.xlsx（2个sheet：AI、答题卡）。
- 要求：界面简洁、提示清晰、运行快、包体尽量小。

二、UI 与交互
1. 右侧上部：拖拽区
- 支持拖入文件：
  - 报名截图：png/jpg/jpeg/webp/heic
  - 源文件：xlsx/xls
- 不仅可拖入文件，选定文件-复制-粘贴到 此拖拽区，也可以实现 输入
- 拖入后显示文件名（最多显示3个，其余显示“等共 N 个文件”）。
- 文件去重：按绝对路径去重。

2. 右侧中部：设置项
- 分配方式（2选1，默认“按页分配”）
  - 按页分配：按 J 列“总页数”作为权重
  - 按标签分配：按 K 列“总评测数量”作为权重
- AI最多可分配页数 M（整数，默认 200）
- 答题卡最多可分配页数 N（整数，默认 300）
- 分配模式（2选1，默认“AI+答题卡一起分给报名人”）
  - 模式A：AI、答题卡独立分配（各自按比例最优）
  - 模式B：AI+答题卡一起分给报名人（尽量保持两表负责人分布一致）

3. 右侧下部：终端
- 输出步骤、进度、警告、错误。
- 日志风格：简短、可读，避免噪声。

4. 底部按钮
- “开始”“停止”与现有工具一致。
- 停止行为：立即中断当前下载/OCR/分配流程，不产出半写入文件。

5. 帮助文案（固定）
“
- 只上传报名截图，则自动下载今日任务的表格（AI+答题卡）
- 上传报名截图 + 表格，则不自动下载
- “配置”中的名单用于校准，可修改
”

三、输入判定与自动下载
1. 文件判定规则
- 源文件优先按文件名识别：
  - 含“AI_待分配” => 源文件1
  - 含“答题卡_待分配” => 源文件2
- 若文件名不命中，则按表头兜底识别：读取 C-M 列，要求包含“子任务ID”“总页数”“总评测数量”核心列。
- 报名截图按扩展名识别（见上）。

2. 自动下载触发条件
- 仅当“拖入了 >=1 张报名截图 且 未拖入任何源文件”时触发自动下载。
- 以下情况不自动下载：
  - 报名截图 + 源文件1
  - 报名截图 + 源文件2
  - 报名截图 + 源文件1 + 源文件2

3. 自动下载目标与命名
- 下载目录：`~/Downloads`
- 下载后重命名为：
  - `AI_待分配.xlsx`
  - `答题卡_待分配.xlsx`
- 重名策略：覆盖旧文件。
    - 触发时提示：已覆盖旧的同名文件

4. 自动下载失败处理
- 未登录页面/权限不足/导出无数据/超时：终端明确报错，并提示用户手动上传源文件继续。
- 每个下载任务最多重试 2 次（总尝试 3 次）。

四、日期与文案生成规则（按系统本地时区计算）
说明：以下“今天”均指本地自然日。

1. AI下载页任务名
- 模板：`yyMMdd-yyMMdd`
- 值：`昨天-今天`
- 示例：
  - 今天 2026-05-12 => `260511-260512`
  - 今天 2026-05-13 => `260512-260513`

2. 答题卡下载页任务名（周周期）
- 模板：`MMDD-MMDD答题卡周期评测`
- 周期定义：每周三到下周二（7天）
- 示例：
  - 2026-05-07 到 2026-05-13 => `0507-0513答题卡周期评测`
  - 2026-05-14 到 2026-05-20 => `0514-0520答题卡周期评测`

3. 输出表 A 列“周期”（月周期）
- 模板：`MMDD-MMDD`
- 周期定义：当月25日到下月24日
- 示例：
  - 2026-05-01 到 2026-05-24 => `0425-0524`
  - 2026-05-25 到 2026-06-24 => `0525-0624`

4. N列“交付日期”
- 默认：明天的“M月D日”（如 `5月12日`）
- 特例：若“明天”为周四，则写为 `M月D日 14:00`（保留空格）
  - 示例：今天 2026-05-13（周三）=> 明天周四 => `5月14日 14:00`

五、名单校准与OCR
1. 配置项
- 在“配置”中提供名单（可编辑），默认：
  `{李橙橙，符于娜，刘雨菲，阎思宇，王哲，崔雅琪，李旻羲，汪哲锐，李梦洁，来晨，王国通，马壮，郭小雨，李梦园，段凯莉，韩正，郝佳益，李迪，蹇文慧，王子怡}`

2. OCR识别目标
- 从报名截图中识别“报名人 + 数量”。
- 支持多张截图，按人名汇总数量。

3. 校准规则
- 先做精确匹配名单。
- 未精确匹配时，做最小编辑距离匹配（阈值 <= 1，且唯一最优才替换）。
- 仍无法匹配则记为“未匹配项”，终端警告并忽略该项，不参与分配。

4. 数量规则
- 同一人多次出现：以最后一个为准，舍弃它前面的。
- 数量 <=0 的条目忽略并警告。
- 若最终有效总数为0：流程报错终止。

六、源文件抽取与预处理
1. 两张sheet的数据来源
- sheet“AI”：从源文件1抽取 C-M 列到结果 B-L 列。
- sheet“答题卡”：从源文件2抽取 C-M 列到结果 B-L 列。

2. 行筛选
- 仅保留“总页数(J) > 0 且 子任务ID非空”的行。
- 先随机打乱（可复现随机种子：当天日期 `yyyyMMdd`）。

3. 上限截断
- AI：抽取后累计 J 列和 <= M。且：J 列和 与 M 的差值小于5%
- 答题卡：抽取后累计 J 列和 <= N。且：J 列和 与 N 的差值小于5%
- 若首行就超过上限，仍保留该首行（避免空结果）。

七、分配算法
1. 约束
- 1个子任务ID只能分配给1个负责人。
- 同一行不可拆分。
- 每个负责人可分到0条（任务不足时允许）。

2. 权重
- 按页分配：使用 J 列值。
- 按标签分配：使用 K 列值。

3. 目标
- 设报名人数配额比为 `p_i`，实际分配权重占比为 `a_i`，目标 `max |a_i - p_i|`小于等于5%，找到符合的可停止寻找，无需最优。

4. 贪心实现（性能优先）
- 对每一条任务，分给“当前最欠配额”的负责人（按 `target_i - assigned_i` 最大）。
- 并列时：
  - 先给当前总条数更少者；
  - 再按姓名字典序。

5. 模式差异
- 模式A（独立分配）：AI、答题卡各自单独跑一次算法。
- 模式B（一起分配）：先跑AI得到负责人配额进度，再在答题卡分配时复用该进度做联动校正，使两表负责人分布更一致。

6. 结果排序
- 结果表中，相同负责人需相邻。
- 分组内按“原始随机序”保持稳定。

八、输出文件格式
1. 文件
- 输出名：`分配表.xlsx`
- 输出目录：App 可执行文件同级目录（与现有 weekly-check 结果一致）。
- 同名覆盖。
- 完成时终端提示：“已生成：分配表.xlsx”，在后面加个文件夹的图标，点击可在Finder中显示。

2. sheet 与列
- sheet顺序：`AI`、`答题卡`
- A列：周期（见第四节）
- B-L：源文件 C-M
- M列：负责人
- N列：交付日期
- O-T：留空

3. 样式
- E、J、K 列表头黄色底色。
- 所有表头开启筛选。

九、性能与体积约束
- 优先复用现有脚本+二进制调用框架，不引入大型新依赖。
- 目标性能：3张截图 + 两个200页量级源表，30秒内完成（不含网络下载等待）。
- 日志降噪，减少无关系统输出。

十、错误码与提示（终端）
- E001：未检测到 有效 报名截图
- E002：自动下载失败 且 缺少 今天任务的表格 
- E003：今天任务的表格 格式不符合要求
- E004：OCR识别 - 无有效报名人数量
- E005：写出 分配表 失败
- E006：[已停止]

十一、验收用例（最少）
1. 仅上传报名截图：自动下载2个源文件并成功生成分配表。
2. 上传报名截图+源文件1：不自动下载，不提示缺少源文件2。仅处理：报名截图+源文件1。
3. 上传报名截图+源文件2：不自动下载，不提示缺少源文件1。仅处理：报名截图+源文件2。
4. 上传报名截图+源文件1+源文件2：不下载，直接处理成功。
5. OCR出现错字：可被名单校准纠正。
6. 明天是周四：N列为“X月X日 14:00”。
7. M/N 上限生效：J列累计不超过阈值（首行超限特例除外）。
8. 任务量明显不足：允许部分负责人分到0条，不报错。
9. 点击停止：流程立即中断，输出E006，不生成损坏文件。

十二、开发落地建议（实现路径）
- UI：新增 DailyAssignPane（拖拽区 + 设置项），接入 RootViewModel。
- 配置：新增 `daily-assign.env`，名单与默认参数可编辑。
- 执行：新增 `每日分配.command`，沿用 PTYTerminalService 与 env 注入。
- 算法与表格处理：放入独立可执行程序（与 check_main_bin 同级思路）以保证速度与稳定性。

十三、终端简略展示：报名人+报名数量/比例+实际分配数量/比例
