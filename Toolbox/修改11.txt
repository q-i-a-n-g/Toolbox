# Toolbox 修改记录 11 - 文件重命名功能开发计划

## 1. 新增功能：文件重命名 (File Renamer)
- **工具定义**：在 `tool_config.json` 中新增 `file-renamer` 工具。
- **自定义界面**：为了严格匹配用户提供的 UI 截图（`文件重命名1.png`, `文件重命名2.png`），将为该工具开发专用的 `FileRenamerView`。

## 2. 交互与 UI 细节
- **拖拽区域**：
    - 提示语修改为：“把 目标文件夹 拖到下面”。
    - 支持拖入文件夹后立即识别路径并加载预览。
- **参数控制（实时预览）**：
    - **前缀**：默认为空，支持实时输入。
    - **起始编号**：默认为 1。
    - **步长**：默认为 1。
    - **编号长度**：默认为空（自然长度），输入数字则自动补零（Padding）。
    - 以上 4 个参数任何变动，下方的“预览”列表将立即更新。
- **预览效果**：
    - 展示格式：“旧文件名 -> 新文件名”。
    - 仅展示前 10-20 条记录，末尾使用 `......` 示意。

## 3. 文件处理逻辑规范
- **过滤规则**：
    - 自动忽略 macOS 系统隐形文件（如 `.DS_Store`）。
    - 自动跳过子文件夹，仅处理当前层级的文件。
    - 不限定文件类型，支持所有文件。
- **排序规则**：
    - **核心要求**：必须符合 macOS 系统的默认名称排序（自然排序/数值排序），例如 `1.jpg`, `2.jpg`, `10.jpg`。
    - **技术实现**：禁止使用简单的 `ls` 命令，应使用 Swift 的 `localizedStandardCompare` 或 `.numeric` 选项进行排序。

- **按钮调整**：
    - “确定”按钮改为“**开始**”，点击执行重命名。
    - “取消”按钮改为“**撤销**”，点击可将最近一次的重命名操作完全还原（回滚到原名）。
- **撤销逻辑**：在内存中维护上一次成功的重命名记录（旧路径 -> 新路径），点击撤销时进行逆向操作。

## 4. 技术实现细节
- **状态管理**：在 `RootViewModel` 中增加 `RenamerState` 结构体，管理当前目录、参数及生成的预览数据。
- **视图集成**：在 `ContentView` 中，当 `selectedTool.id == "file-renamer"` 时，展示定制的重命名界面。
- **原子操作**：执行重命名时，应逐一调用 `FileManager.moveItem`，并在终端记录执行过程及最终结果。

## 5. 补充建议
- **重名冲突处理**：在预览阶段，如果新文件名与现有文件或其它新文件名冲突，应在预览中用红色高亮提醒。
- **执行记录**：由于重命名是破坏性操作，建议在执行成功后，终端输出中提供一个简单的说明或日志文件路径。
